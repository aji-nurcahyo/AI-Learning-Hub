# GS-08: Project Structure, Dataset Management & Troubleshooting

Modul ini menetapkan standar arsitektur direktori proyek kecerdasan buatan, tata kelola dataset yang bertanggung jawab, pencegahan kebocoran kredensial (*secrets management*), serta katalog solusi untuk empat kendala teknis yang paling sering dialami pengembang pemula.

## Tujuan

Setelah menyelesaikan modul ini, Anda diharapkan mampu:
1. Menyusun struktur direktori proyek AI yang modular, bersih, dan mudah direproduksi.
2. Membedakan pengelolaan data mentah (*raw data*) yang tidak boleh dimodifikasi dengan data olahan (*processed data*).
3. Menggunakan path relatif (`pathlib.Path`) untuk mencegah kegagalan eksekusi saat kode dipindahkan ke komputer lain.
4. Menerapkan protokol keamanan agar API key dan data sensitif tidak terunggah ke repository publik.
5. Menyelesaikan empat kendala teknis fundamental: `ModuleNotFoundError`, kernel mismatch, `FileNotFoundError`, dan kegagalan kompilasi paket.

## Prinsip Tata Kelola Dataset

1. **Prinsip Immutability Data Mentah**:
   File di dalam `data/raw/` harus dianggap sebagai arsip baca-saja (*read-only*). Segala proses imputasi data hilang, pembersihan teks, atau reduksi fitur harus ditulis dalam script dan disimpan sebagai file baru di `data/processed/`.
2. **Path Relatif vs Path Absolut**:
   - **HINDARI PATH ABSOLUT**: `pd.read_csv("C:/Users/NamaSaya/Documents/project/data.csv")` akan langsung error saat dieksekusi di komputer rekan tim, server, atau Colab!
   - **GUNAKAN PATH RELATIF**:
```python
from pathlib import Path
import pandas as pd

# Menemukan path direktori root proyek secara dinamis
BASE_DIR = Path(__file__).resolve().parent.parent
data_path = BASE_DIR / "data" / "raw" / "dataset.csv"

df = pd.read_csv(data_path)
```
3. **Dokumentasi Lisensi & Atribusi Sumber**:
   Setiap dataset yang digunakan wajib disertai catatan asal-usul (*provenance*), URL sumber resmi, dan lisensi hak cipta (misalnya CC-BY 4.0, Open Database License, atau domain publik). Jangan melatih sistem menggunakan data personal tanpa persetujuan subjek data (*informed consent*).
4. **Pencegahan Kebocoran Kunci Rahasia (*API Keys*)**:
   Jangan pernah menuliskan token API (OpenAI, HuggingFace, Kaggle, dll.) langsung di dalam kode script atau sel notebook. Simpan pada berkas `.env` lokal dan panggil via `os.getenv()`, serta pastikan `.env` telah tercatat di dalam `.gitignore`.

## Katalog Pemecahan Masalah (Troubleshooting Guide)

| Gejala Error | Akar Masalah | Solusi Terverifikasi |
|---|---|---|
| **`ModuleNotFoundError: No module named 'xyz'`** | Modul belum terpasang di environment yang sedang aktif, atau VS Code menggunakan interpreter yang salah | 1. Pastikan virtual environment aktif `(.venv)`<br/>2. Jalankan `python -m pip install xyz`<br/>3. Di VS Code, tekan `Ctrl+Shift+P` → `Python: Select Interpreter` → pilih `.venv` |
| **Kernel Mismatch di Notebook** | Tampilan notebook berjalan di kernel Python global sistem, bukan di kernel virtual environment | 1. Di pojok kanan atas notebook VS Code, klik **Kernel Selector**<br/>2. Pilih **Python Environments...**<br/>3. Arahkan ke interpreter `.venv` Anda |
| **`FileNotFoundError: [Errno 2] No such file or directory`** | *Working directory* terminal berbeda dengan lokasi file yang Anda asumsikan | 1. Periksa folder aktif dengan `import os; print(os.getcwd())`<br/>2. Buka folder kerja dengan menu **File → Open Folder** di root proyek<br/>3. Gunakan modul `pathlib.Path` untuk konstruksi path yang tahan lintas OS |
| **Gagal Kompilasi Paket saat `pip install`** | Paket memerlukan compiler C++ (seperti Microsoft C++ Build Tools) karena wheel binary belum tersedia | 1. Periksa versi Python Anda (gunakan versi stabil 3.11/3.12, bukan rilis alpha/beta)<br/>2. Perbarui pip: `python -m pip install --upgrade pip setuptools wheel` |
