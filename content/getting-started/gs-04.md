# GS-04: Virtual Environment & Package Management

Modul ini memandu Anda mengisolasi dependensi proyek kecerdasan buatan menggunakan *Virtual Environment* (`venv`) dan mengelola pustaka dengan `pip` secara aman.

## Tujuan

Setelah menyelesaikan modul ini, Anda diharapkan mampu:
1. Menjelaskan mengapa setiap proyek AI memerlukan *Virtual Environment* terpisah guna menghindari konflik versi antar pustaka (*dependency conflict*).
2. Membuat dan mengaktifkan virtual environment pada Windows (PowerShell dan Command Prompt), macOS, dan Linux.
3. Memasang dependensi menggunakan perintah aman `python -m pip install`.
4. Mendokumentasikan dan memulihkan lingkungan dengan berkas `requirements.txt`.
5. Mengatasi kendala eksekusi skrip di PowerShell tanpa mengubah kebijakan keamanan sistem operasi secara global.

## Mengapa Virtual Environment Sangat Krusial?

Dalam ekosistem AI:
- Proyek A mungkin membutuhkan `scikit-learn==1.3.0` dan `numpy<2.0.0`.
- Proyek B mungkin menggunakan fitur terbaru `torch` yang membutuhkan `numpy>=2.0.0`.
Jika semua paket dipasang pada instalasi Python global sistem, versi yang saling bertentangan akan menimpa satu sama lain dan merusak kedua proyek. Virtual environment menciptakan direktori mandiri yang menampung interpreter dan paket khusus untuk satu folder proyek.

## Langkah Praktik

### 1. Membuat Virtual Environment
Buka terminal pada direktori proyek Anda, lalu jalankan:

```bash
python -m venv .venv
```
Perintah ini akan membuat sebuah folder tersembunyi bernama `.venv` yang berisi salinan mandiri dari interpreter Python dan pustaka standar.

### 2. Mengaktifkan Virtual Environment
Perintah aktivasi berbeda tergantung sistem operasi dan jenis shell:

- **Windows (PowerShell)**:
```powershell
.venv\Scripts\Activate.ps1
```
- **Windows (Command Prompt / cmd.exe)**:
```cmd
.venv\Scripts\activate.bat
```
- **macOS / Linux (Bash / Zsh)**:
```bash
source .venv/bin/activate
```

*Tanda Keberhasilan:*
Prompt terminal Anda akan diawali dengan nama environment dalam tanda kurung, misalnya:
`(.venv) PS D:\ai-projects> `

### 3. Mengapa Menggunakan `python -m pip`?
Selalu gunakan:
```bash
python -m pip install <nama_paket>
```
Daripada sekadar mengetik `pip install <nama_paket>`.
**Alasannya:** Menjalankan `python -m pip` menjamin 100% bahwa paket akan dipasang ke dalam interpreter Python yang sedang aktif di terminal saat itu, bukan ke instalasi Python lain yang kebetulan lebih dulu terdaftar dalam urutan PATH sistem.

### 4. Mengelola File `requirements.txt`
Untuk mencatat semua paket yang terpasang dan versinya agar proyek Anda dapat direproduksi oleh orang lain:
```bash
python -m pip freeze > requirements.txt
```

Untuk memasang ulang seluruh dependensi dari file `requirements.txt` pada lingkungan baru:
```bash
python -m pip install -r requirements.txt
```

### 5. Menonaktifkan Environment
Jika Anda telah selesai bekerja pada proyek tersebut:
```bash
deactivate
```
Prompt terminal akan kembali normal tanpa awalan `(.venv)`.

## Checkpoint Keberhasilan

- [ ] Folder `.venv` berhasil tercipta di dalam folder proyek Anda.
- [ ] Terminal menampilkan tanda `(.venv)` saat environment aktif.
- [ ] Menjalankan `python -c "import sys; print(sys.prefix)"` mencetak path yang mengarah ke folder `.venv` Anda.

## Troubleshooting

- **Kendala PowerShell: "cannot be loaded because running scripts is disabled on this system"**
  *Penyebab:* Fitur keamanan PowerShell membatasi eksekusi file `.ps1` yang tidak ditandatangani.
  *Solusi yang Aman:* **JANGAN** pernah mengubah kebijakan keamanan seluruh komputer secara global (jangan jalankan `Set-ExecutionPolicy Unrestricted` secara global). Sebagai gantinya, jalankan kebijakan khusus untuk sesi terminal yang sedang terbuka saja:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.venv\Scripts\Activate.ps1
```
  Atau gunakan terminal **Command Prompt (cmd.exe)** di VS Code yang tidak memiliki batasan file `.ps1`:
```cmd
.venv\Scripts\activate.bat
```
- **Jangan Commit Folder `.venv` ke Version Control (Git)**
  Folder `.venv` berukuran ratusan megabyte dan bersifat spesifik untuk mesin Anda. Selalu tambahkan baris `.venv/` ke dalam file `.gitignore`.
